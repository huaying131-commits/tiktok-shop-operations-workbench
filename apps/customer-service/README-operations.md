# 马来西亚示例店运营工作台

打开 [店铺运营工作台](http://127.0.0.1:3377/operations)。重启 Windows 后如果页面打不开，双击同目录的 `start-operations.cmd`。工作台会复用已保存的授权配置，授权服务未启动时由原启动器拉起。后台运行期间可以关闭工作台网页和 ChatGPT 对话。电脑休眠或关机时，本机后台暂停。

首页从今日 GMV、支付订单、发布进度和待发货开始，下面可看广告投流、各仓待发货、五账号发布进度和今日待办。广告默认看当天，支持切换近 7 个完整自然日。它用广告账户币种，店铺成交用 MYR。平台 GMV 与订单买家实付分列，发布账本与平台公开总数分列。商品图和原视频只展示已匹配的素材。

[原版工作台](http://127.0.0.1:3377/operations?view=legacy)保留历史入口。新版导航和原岗位书签都可以打开对应的新版业务页。

同一台电脑上的 AI 可直接读取 `GET /api/operations/dashboard`（`schema: operations-dashboard/v1`）。`suggestions` 带建议、依据和下一步，`roleTasks` 带稳定任务键、岗位、状态和更新时间。`fulfillment` 及 `workflow.publication` 区分已核和待核。时间窗以 `start`（含）和 `endExclusive`（不含）表达，空值表示未核。`GET /api/operations/dashboard?day=YYYY-MM-DD` 可查看某日的可用回执。该入口仅限本机，同一岗位仍用既有工作流程执行。

| 页面 | 数据和进度 |
| --- | --- |
| 任务中心 | 查看待处理、待复验和待决策。展开任务可核对规格、下一步与本地回执。 |
| 后台运行 | 分别显示备货建议和好视频分析的最近一轮回执、尝试次数与下次重试时间。 |

| 待跟进 | 展示待发货、原发布账本、商家折扣和秒杀关系的缺口。活动关系每天读取一次，平台官方活动、店铺券和成交价另有口径。 |

| 日报 | 按马来西亚自然日保存数据和结果回执。每个自然日一份小型摘要，本机保留取数时间。 |

`GET /api/operations/tasks` 读取本机 SQLite 台账，支持同样的 `role` 筛选。刷新面板读取最新回执。开发测试可用 `TTS_OPERATIONS_QUEUE_DIR` 指定独立台账，配合 `DESK_PORT=0` 选择测试端口及 `TTS_OPERATIONS_BOARD=0` 关闭该实例的店铺取数循环。

## 视频制作取商品图

用同一 Windows 用户和现有 TikTok Shop 授权运行 `scripts/operations/read-product-reference.mjs`。`--query SU-57` 读取马来西亚示例店在售目录，返回可匹配的商品和变体。`--product-id 9000000000000000016 --sku-id 9000000000000000018` 会复查银灰变体并下载官方 SKU 图。图片和来源记录保存在 `outputs/operations-product-reference/<SKU>/<采集时间>/`。多变体商品缺少精确素材时，记录缺图。单变体可取商品相册并标明来源。

已从马来西亚示例店实店按机型查到银灰和深绿 SU‑57，并下载两张各自的 800×800 SKU 图。云端查询可沿用同一套 SKU 选择和图片校验。计划给 Muse 提供自定义 HTTPS API，给 Grok Bot 提供远程 MCP。两者云端接入尚待部署验收。每次返回商品、精确 SKU、颜色、来源时间和可下载文件。需要更多拍摄角度时，再挂接同一 SKU 已核过的实拍素材。

## 谁在调度

工作台有网页界面和 Node.js 后台。Node.js 在本机定时调用已有的 3000 端口授权服务，复用加密保存的店铺授权。App Key 和 App Secret 用于识别应用和签名，店铺授权令牌决定可调用的业务范围。TikTok Shop 响应业务请求，本机后台负责时序和结果记录。

工作台页面打开时每 15 秒检查一次新回执，后台标签恢复可见时立即检查。点击右上角刷新可请求后台按各自的取数间隔检查。展开「数据更新时间」可以分别查看查询时间、报表覆盖日期和历史回执。

本机服务每约 5 分钟检查支付订单、买家实付和发货状态总数，每约 30 分钟检查商品目录、官方 GMV 和广告。广告使用原 Windows 用户已有的 TikTok for Business 授权，于马来西亚时间 08:00–24:00 运行 `read-gmv-max.mjs --dashboard-only`。发货总数使用最新可核的订单状态，分仓与 SKU 明细继续按原包裹和仓库回执显示。视频发布读取原岗位账本，平台公开数量以独立回查为准。仓库库存、视频表现、采购与结算按各自回执更新。单个来源读取失败时保留原回执和取数时间。

经营方案沿用 Claude 的分层设计和原岗位记录。确定步骤交脚本执行，需要判断的任务由模型结合证据给出决策，实际动作由对应执行器交付，再以平台结果回查。工作台现已自动完成取数、商家活动覆盖核查和日报。原业务排程在岗位进度中显示，新的写入执行器仍需真实样本验收。

备货与好视频由 Windows 任务 `DaleiShopOps-MY-DailyRoleQueue` 独立执行。北京时间 08:00–24:00 每 5 分钟检查一次，每项只完成当前自然日的一次读取。暂时失败保留上次证据，并按 5、10、20、40、60 分钟退避。任务以当前 Windows 用户交互式上下文运行，用户需保持登录，电脑休眠时没有取数。原授权及代理可用后继续，网页和 Codex 聊天可关闭。`scripts/operations/start-daily-role-queue.ps1` 是同一运行入口。

Codex 内的「马来西亚示例店运营任务派送」在可运行时检查新增任务，只向各原窗口交接任务索引。SQLite 按稳定任务键及岗位保留派发记录，已交接的对象更新证据时不重复唤醒。窗口暂不可用时，岗位仍可在工作台查到任务。采购草案等大磊确认及实际报价回执。制作队列先交对照脚本，已完成且合格的成片沿原制作→发布流程继续。

## 数据位置

日报保存在 `data/operations-board/days/`，活动覆盖回执保存在 `data/operations-board/promotion.json`，试点回执保存在 `data/operations-board/pilot-receipts/<活动ID>/`。`config/operations-trial-defaults.json` 的 `trackedPromotionPilot` 指向有真实创建和回查凭证的试点目录。约 30 分钟的取数循环同时回查该活动及准确 SKU，出单后按订单、商品、SKU 和订单行记录买家商品价、折扣和账单明细。账单索引提供平台标记的付款状态。到期后沿用空活动回执的条件为完整订单窗口、各页请求号齐全、实读总数与平台总数一致、准确 SKU 订单明细和平台使用量均为 0。

`node scripts/operations/run-daily-work.mjs` 可立即生成当前试点的总控回执，使用 `--pilot-dir` 可核另一套已实际创建的试点。财务显示最近一次订单结算快照及准确订单的独立回查。试点取数改动已在隔离工作台上调用真实接口验收。运行中的工作台会在下次正常启动时加载新版模块。

加 `--refresh-promotion-sales` 可按新品折扣候选的实际建品时间连续分页核订单。总控同时显示商品和准确规格的匹配结果。新品折扣表单资格、平台券叠加和实物库存仍以各自的实店及仓库回执为准。

加 `--refresh-promotion-checkout` 可对当前商家活动覆盖的近七日订单抽样，每个活动最多四笔。按订单、SKU 和订单行读买家商品额、商家让利、SKU 净结算和账单付款。活动归属以订单明细返回的活动 ID 为准。

总控实跑同时读取当日视频商品流量，保存全部账号、官方号、营销号和联盟账号四种口径的官方请求号、商品曝光、点击及归因 SKU 订单。发布条数仍从准确视频 ID 和原发布回执核对。

加 `--refresh-statement-payments` 可更新原账单索引。有准确付款 ID 的已付款账单会再查官方付款记录，回执区分账单状态、付款记录和银行到账。

结算复盘按相同订单与交易 ID 核对仍未结算的预估变动。单独执行 `node scripts/operations/run-service-fulfillment-read.mjs --open-aftersales` 可只查当前待审退货退款和仲裁，并在总控显示该次结果。换货和换新使用原七天更新窗口。

总控脚本也按商品 ID、SKU ID 和商家 SKU 核对官方库存查询结果，记录平台可售量、已占用量及各仓数据。平台未返回的活动和达人分配字段留空。实物可发量继续以仓库或供货证据为准。

`node scripts/operations/run-daily-work.mjs --refresh-fulfillment-routing --refresh-pending-packages --read-overseas-wms --read-domestic-wms` 先分页读取最新七天官方订单，再按准确订单行、仓库和运输方式分流，回查原包裹与承运轨迹。马来海外仓待发货和待揽收订单查神牛、战马记录。中国直发待揽收原包裹查好货来打包和售后卡记录，待发货单包裹同步运行逐单备货核对并保留各自回执。好货来查询在本机独立 PowerShell 进程内直连。包裹、件数、仓库出库、承运揽收及两仓同时处理分别记录。只追踪已有分仓名单时可省略 `--refresh-fulfillment-routing`。指定原退件时可运行 `node scripts/operations/read-return-warehouse.mjs <原退货物流回执>`，按原订单与退件运单匹配神牛退货单，并在下次日报显示签收证据。命令均为只读，按履约岗位现行工作时段使用。

中国直发单包裹可用 `node scripts/operations/read-domestic-packing.mjs --routing <当天分仓回执> --order-id <原订单ID>` 复查。它分别核对平台原单、取消申请和退货退款，再查好货来六个状态、历史货品对应关系、当前可用库存及售后卡。取消或退货退款有记录时，生成待核回执并显示在总控。七日内缺少同 SKU 历史时，用 `--history <原仓库订单回执>` 关联更早的订单，仍会独立回读该原单。总控显示备货方案和待提交状态，原岗位接续时按当时的实际订单状态、库存、费用及授权确认。

`--refresh-pending-packages` 同时复查待发订单的原包裹及备货时限。对平台确认仍待发的准确中国直发单包裹，查询可投递状态和已有面单。回执保留请求号、运单号是否存在及面单可用状态，省略下载地址、运单号原文和投递点资料。较新的平台回执仍确认原单与包裹待发时，总控可显示同日较早的仓库备货证据，并标原库存读取时间。实际打包、运单生成、仓库出库和承运商扫描分别记证。
